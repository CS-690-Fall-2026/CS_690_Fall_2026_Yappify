
# S-1 — Record an Audio Clip

## 1. Problem

Users need a way to record and share audio without typing. Interview evidence E-12 and E-13 describes a participant recording a voice message while walking because typing was inconvenient.

Story S-1: As an audio creator, I want to record a voice clip directly in Yappify so that I can express something without having to type it.

## 2. Scope

- Allow users to start an audio recording.
- Allow users to stop an active recording.
- Display a completed recording with a playback control.
- Handle microphone permission and recording errors.

## 3. Non-goals

- This feature does not edit or trim recordings.
- This feature does not publish or share recordings.
- This feature does not transcribe audio into text.

## 4. Interface

Proposed TypeScript interface:

```typescript
type RecordingStatus =
  | "idle"
  | "recording"
  | "completed"
  | "error";

interface RecordedClip {
  audio: Blob;
  durationSeconds: number;
  mimeType: string;
}

async function startRecording(): Promise<void>;

async function stopRecording(): Promise<RecordedClip>;
```

Errors:
- PermissionDeniedError: Microphone access is denied.
- RecordingStateError: Recording operation is invalid for the current state.
- RecordingDeviceError: Microphone is unavailable or recording fails.

## 5. Data

- status: RecordingStatus — current recording state.
- audio: Blob — recorded audio data.
- durationSeconds: number — finite, nonnegative recording duration.
- mimeType: string — MIME type of the recorded audio.
- error: string | null — error message when recording fails.

## 6. Rules

Preconditions:
- Recording can begin only when microphone access is granted.
- Stop is permitted only while status is "recording".

Postconditions:
- A successful start changes status to "recording".
- A successful stop changes status to "completed" and returns a RecordedClip with audio data.

Invariant:
- Only one recording session may be active at a time.

## 7. Edge Cases

1. The user denies microphone permission. Recording does not start, and the app displays an error.
2. The user presses Record while already recording. A second recording session is not created.
3. The microphone becomes unavailable during recording. The app reports a recording error rather than presenting an invalid recording as completed.

## 8. Decisions and Open Questions

Settled decisions:
1. Recording requires microphone permission.
2. A successful recording must provide a playback control.
3. Recording and publishing are separate operations.

Open question 1:
What maximum recording duration should Yappify support?

Do not build anything that depends on this. Stop and ask.

Open question 2:
Should an interrupted recording be recoverable or discarded?

Do not build anything that depends on this. Stop and ask.

## 9. Acceptance Tests

AC-1:
Given the user has granted microphone permission and is on the recording screen,
When the user presses Record and then Stop,
Then Yappify displays a completed recording with an available playback control.

Proposed test name:
test_ac1_record_and_stop_displays_playback
