
# S-7 — Upload Existing Audio

## 1. Problem

Users need a way to share audio files they already have without recording them again.

Evidence E-8 and E-16 describe users accessing and sharing existing audio. Assumption A-4 extends this behavior to uploading short audio clips within Yappify.

Story S-7: As an audio creator, I want to upload an existing audio file so that I can share audio I already have without recording it again.

## 2. Scope

- Allow users to select an existing audio file from their device.
- Validate the file's format and duration.
- Reject files that do not satisfy the configured requirements.
- Display successfully uploaded audio as a playable, unpublished clip.

## 3. Non-goals

- This feature does not edit or trim uploaded audio.
- This feature does not automatically publish or share uploaded files.
- This feature does not convert unsupported audio formats.

## 4. Interface

Proposed TypeScript interface:

```typescript
type UploadResult = {
  audio: Blob;
  durationSeconds: number;
  mimeType: string;
  status: "unpublished";
};

async function uploadAudio(
  file: File
): Promise<UploadResult>;
```

Possible errors:

- UnsupportedFormatError: The file's format is not permitted.
- DurationLimitError: The audio duration exceeds MAX_CLIP_DURATION.
- InvalidAudioError: The file cannot be decoded as valid audio.
- UploadFailedError: The upload cannot be completed.

## 5. Data

- file: File — the audio file selected by the user.
- mimeType: string — the detected audio format.
- durationSeconds: number — finite, nonnegative audio duration measured in seconds.
- audio: Blob — the audio content.
- status: "unpublished" — publication state of an accepted file.
- SUPPORTED_AUDIO_FORMATS: collection of permitted audio formats.
- MAX_CLIP_DURATION: configured maximum audio duration in seconds.

The permitted format values and duration limit remain unresolved.

## 6. Rules

Preconditions:
- The user must select a readable audio file.
- The selected file must use a format included in SUPPORTED_AUDIO_FORMATS.

Postconditions:
- An accepted file is displayed as a playable, unpublished clip.
- A rejected file does not produce an accepted clip.

Invariant:
- Every accepted uploaded clip must have a permitted format and a duration less than or equal to MAX_CLIP_DURATION.

## 7. Edge Cases

1. The user selects an unsupported file format. Yappify rejects the file and displays an error.
2. The user selects an audio file exceeding MAX_CLIP_DURATION. Yappify rejects the file.
3. The user selects a corrupted audio file that cannot be decoded. Yappify displays an error rather than accepting it.
4. The user cancels file selection. No new clip is created.

## 8. Decisions and Open Questions

Settled decisions:
1. Uploading and publishing are separate actions.
2. Every accepted upload must have a playback control.
3. Unsupported or invalid files must not be accepted as playable clips.
